## 二、PID 控制：工业界最常用的控制器

**不用知道系统的精确模型，只要调三个参数就能work** —— 这是 PID 几十年不倒的原因。

```
输出 = Kp·e + Ki·∫e dt + Kd·(de/dt)
       ↑       ↑          ↑
     比例项   积分项     微分项
```

| 项 | 作用 | 直觉 | 太大会怎样 |
|:---|:---|:---|:---|
| **P**（比例） | 按当前误差出力 | **"差多少补多少"** | 震荡 |
| **I**（积分） | 累积历史误差 | **"一直差就一直加力"** | 超调、积分饱和 |
| **D**（微分） | 按误差变化率出力 | **"快到了就提前刹车"** | 对噪声敏感 |

**三项各解决一个问题：**
- **P** 让系统动起来
- **I** 消除稳态误差（比如坡度导致的持续偏差）
- **D** 抑制震荡（预测趋势，提前收敛）

## 三、本作业的具体实现

```python
class Controller:
    def update(self, target, current, dt):
        error = target - current

        # 比例项
        p_term = self.kp * error

        # 积分项（累积）
        self.integral += error * dt
        i_term = self.ki * self.integral

        # 微分项（变化率）
        derivative = (error - self.prev_error) / dt
        d_term = self.kd * derivative
        self.prev_error = error

        return p_term + i_term + d_term
```

**关键细节：`dt`（时间步长）。**

- 积分要乘 `dt`（累积的是"误差 × 时间"）
- 微分要除 `dt`（变化率 = 变化量 / 时间）

**这是新手最容易漏的地方** —— 忘了 `dt` 会让参数失去物理意义。

## 四、自动驾驶里的特殊情况

### ① 执行器饱和

油门只能 0~1，刹车也是。**PID 输出可能超出范围。**

```python
throttle = np.clip(pid_output, 0.0, 1.0)
```

### ② 积分饱和（Integral Windup）⭐

**问题：** 如果目标速度一直达不到（比如上坡），积分项会越积越大，
等到能达到了，积分已经"冲过头"，导致严重超调。

**解法：**

```python
# 方法一：限幅
self.integral = np.clip(self.integral, -MAX, MAX)

# 方法二：只有在不饱和时才积分
if not is_saturated:
    self.integral += error * dt

# 方法三：反算（back-calculation）
self.integral += error * dt + (saturated_out - out) * Kb * dt
```

**这是实际控制工程里必考的点。**

### ③ 前馈（Feedforward）

**PID 是"反馈"—— 等误差出现了才纠正。但有些东西可以提前知道：**

```python
# 想要的加速度 a_des，可以算出"维持这个加速度大概需要多少油门"
feedforward = mass * a_des / max_force
throttle = feedforward + pid_correction
```

**前馈负责"大致对"，PID 负责"精细修"** —— 这是工业控制的标准架构。

## 五、参数怎么调

**经典方法（Ziegler-Nichols）：**

1. 先只开 P，`Ki = Kd = 0`
2. 增大 `Kp` 直到系统开始**持续震荡**（临界增益 `Ku`）
3. 记下震荡周期 `Tu`
4. 按表查参数：`Kp = 0.6·Ku`，`Ki = 1.2·Ku/Tu`，`Kd = 0.075·Ku·Tu`

**实践中更常用的做法：手动调**
- 先调 P 到响应够快
- 加 D 抑制超调
- 最后加 I 消除稳态误差

**判断标准：**
- **上升时间** —— 多快达到目标
- **超调量** —— 冲过头多少
- **稳态误差** —— 最终差多少
- **调节时间** —— 多久稳定下来

## 七、PID 的局限与后续

| 问题 | 更好的方案 |
|:---|:---|
| 无法处理强非线性 | 模型预测控制（MPC） |
| 参数不随工况变化 | 增益调度（Gain Scheduling） |
| 不利用已知模型 | 状态反馈 / LQR |
| 有约束时表现差 | MPC（天然支持约束） |

**现代自动驾驶普遍用 MPC** —— 因为它能同时处理：
- 系统动力学模型
- 执行器约束（油门范围）
- 安全性约束（不能撞）
- 舒适性（加速度平滑）

**但 PID 依然是"先跑起来"的第一选择** —— 十分钟能调出来，MPC 要建一整套模型。
