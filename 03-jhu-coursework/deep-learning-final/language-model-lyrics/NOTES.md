# 原理讲解：字符级语言模型与 LSTM

> 这个作业教**「让网络学会写歌词」**，本质是**序列建模**。
> 它是 GPT 那类模型的**最小可运行版本** —— 同样的任务，只是规模差了几个数量级。

---

## 一、任务：给定前文，预测下一个字符

```python
输入:  "I love you"
目标:      " love you "
          ↑ 每个位置都预测下一个字符
```

**这叫「自回归语言模型」** —— 用前面的内容预测下一个 token，
然后把自己预测的输出再喂回去，就能一直生成下去。

---

## 二、为什么需要 RNN 而不是普通网络

**普通全连接网络的问题：输入长度固定。**

但文本长度可变，而且**上下文关系跨越很远**：
"I grew up in France ... I speak fluent ___" —— 要填 "French"，
得记住很远处的 "France"。

**RNN 的解法：维护一个「隐藏状态」，随序列传递。**

```
h_t = tanh(W_h · h_{t-1} + W_x · x_t + b)

   h_t  ← 当前记忆（融合了之前所有信息）
   x_t  ← 当前字符
```

**每一步都把「之前所有信息」压缩进 `h`。**

---

## 三、RNN 的致命问题：梯度消失

**训练时要沿时间反向传播（BPTT）。梯度要连乘很多个 `W_h`：**

```
∂L/∂h_1 = ∂L/∂h_T · ∏(∂h_t/∂h_{t-1})
                    ↑
              连乘 T 次
```

- 如果这些因子 < 1 → **梯度消失**，学不到长距离依赖
- 如果 > 1 → **梯度爆炸**，训练发散

**后果：** 普通 RNN 只能记住 5~10 步之前的事。

---

## 四、LSTM：用「门」控制记忆

**1997 年提出的解法 —— 引入一个「细胞状态」`C`，用三个门控制它：**

| 门 | 作用 | 直觉 |
|:---|:---|:---|
| **遗忘门** `f` | 决定丢掉多少旧记忆 | 「这事不重要了，忘了吧」 |
| **输入门** `i` | 决定写入多少新信息 | 「这个要记住」 |
| **输出门** `o` | 决定输出多少记忆 | 「现在只说出相关的部分」 |

```python
f = sigmoid(W_f @ [h_prev, x] + b_f)     # 遗忘
i = sigmoid(W_i @ [h_prev, x] + b_i)     # 输入
g = tanh   (W_g @ [h_prev, x] + b_g)     # 候选记忆
o = sigmoid(W_o @ [h_prev, x] + b_o)     # 输出

C = f * C_prev + i * g                    # ← 更新细胞状态（关键）
h = o * tanh(C)
```

**关键在第 5 行：** `C` 的更新是**加法**而不是乘法。

**为什么这解决了梯度消失？** 加法项 `f * C_prev` 让梯度能**几乎无衰减地**流回去 ——
就像给梯度修了一条「高速公路」。

## 五、字符级模型的细节

**为什么用「字符」而不是「词」？**

| | 字符级 | 词级 |
|:---|:---|:---|
| 词表 | 几十个（a-z + 标点） | 几万到几十万 |
| 长距离依赖 | 更长（一个词拆成多步） | 更短 |
| 拼写错误 | 能生成新词 | 只能是词表里的 |
| 适合入门 | ✅ **小、快、能看懂** | ❌ 需要大词表 |

**训练数据：** 歌词语料（本仓库不含数据集）

## 六、生成：温度参数

**训练完，怎么生成？**

```python
logits = model(x)                     # 得到每个字符的分数
probs  = softmax(logits / temperature)
next_char = sample(probs)             # 按概率采样（不是取最大值！）
```

**`temperature` 控制「创造力」：**

| 温度 | 效果 |
|:---:|:---|
| **0.2** | 保守、重复、像原文（接近取 argmax） |
| **0.8** | 平衡，通顺且有变化 |
| **1.5** | 混乱、随机、拼出奇怪的词 |

**这是个很直观的实验** —— 建议自己跑几档看看。

## 七、从这里到 GPT

| | 这个作业 | GPT-3 | 
|:---|:---|:---|
| 任务 | 预测下一个**字符** | 预测下一个 **token** |
| 结构 | LSTM | **Transformer** |
| 规模 | 几层，几千参数 | 96 层，1750 亿参数 |
| 训练数据 | 歌词语料 | 整个互联网 |

**任务形式完全一样，只是「用什么网络」和「多大规模」的区别。**

**Transformer 取代 LSTM 的原因：** 注意力机制可以**并行**处理整个序列
（LSTM 必须一步步来），所以能榨干 GPU，才能训到那么大。

**建议的改进方向：**
- **多层 LSTM + Dropout** —— 提升容量同时防过拟合
- **梯度裁剪** —— `clip_grad_norm_`，防梯度爆炸
- **换 GRU** —— 比 LSTM 参数少、训练快，效果常常接近
- **Attention** —— 在这基础上加注意力，就是通往 Transformer 的路
