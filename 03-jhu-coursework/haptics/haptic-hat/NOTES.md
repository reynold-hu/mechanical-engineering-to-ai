# 原理讲解：触觉避障帽（Haptic Interface Design）

> 课程：**EN.530.691** Haptic Interface Design for Human-Robot Interaction
> 这个项目教**「信息怎么通过触觉传递给人」** —— 人机交互里最少被讨论的通道。

---

## 一、为什么用「触觉」而不是「听觉」

给视障人士做避障提示，常用的做法是**声音**（滴滴声）。但听觉有问题：

| 通道 | 优势 | 劣势 |
|:---|:---|:---|
| **听觉** | 反应快、易实现 | 🚫 **视障人士本就依赖听觉** —— 用声音提示会**占用他们最主要的感知通道**（听不清车声、人声） |
| **触觉** | **不占用听觉**、可穿戴、私密 | 空间分辨率低、需要学习 |

**核心判断：不该用「使用者赖以生存的通道」去传递新信息。**

**这就是 Haptic Interface 这门课的意义** —— 设计让人「通过皮肤感知信息」的接口。

---

## 二、触觉反馈的三种类型

| 类型 | 机制 | 例子 |
|:---|:---|:---|
| **振动触觉** | 电机偏心旋转 | 手机振动（本项目用的） |
| **力反馈** | 施加实际的反作用力 | 游戏方向盘、手术机器人 |
| **皮肤拉伸** | 侧向拉扯皮肤 | 高级触觉研究 |

**本项目用的是最基础的振动电机** —— 成本低、功耗小、可穿戴。

---

## 三、信息怎么编码：触觉设计的关键问题

**振动电机只能控制两件事：何时振、振多强。** 那怎么编码"障碍物在哪个方向"？

| 编码方式 | 做法 | 优点 | 缺点 |
|:---|:---|:---|:---|
| **空间编码** | 多个电机放不同位置（左/中/右） | **直观，不用学** | 需要多个电机 |
| **时间编码** | 用一个电机，用不同节奏表示 | 省硬件 | **需要学习** |
| **强度编码** | 振动强弱表示距离 | 直观 | 区分度低 |

**本项目的目录结构 `Final_singleloop` 暗示用的是单电机方案**，
可能是时间编码的雏形。

> 📖 Haptics 领域的经典参考是 Tan et al. 的 "Tactual displays for wearable computing"，
> 里面系统比较了几种编码方式的辨识度。

## 四、技术实现

**硬件（从四个版本的目录能看出迭代过程）：**

```
Sensor/Ultrasonic_Sensor_Ranging_Test/    ← 第一步：超声波测距能不能用
Sensor/                                    ← 第二步：传感器封装
Final_singleloop/                          ← 第三步：单回路闭环
Final_Verison/                             ← 第四步：最终版
```

**核心逻辑：**

```cpp
loop() {
    distance = ultrasonic.read();          // 测距
    if (distance < THRESHOLD) {
        vibrate(STRENGTH_MAP(distance));   // 越近振得越强
    } else {
        stop_vibrating();
    }
}
```

**为什么用超声波不用红外？**
- 超声波对**透明物体和深色物体**都能测（红外不行）
- 探测角度宽，适合"扫描前方"
- 便宜

**缺点：** 对软性材料（衣服、海绵）测距不准，且多个传感器之间会互相干扰。

## 五、这门课的核心问题：人机闭环

课程描述里写的是
*"human-in-the-loop feedback control"* —— **人是控制回路的一部分**。

```
      ┌──────────────────────────────┐
      │                              │
  环境 ──▶ 传感器 ──▶ 触觉提示 ──▶ 人
      ▲                              │
      └──────── 人的动作 ◀───────────┘
```

**和纯机器人控制的区别：**
- **人的反应有延迟**（约 200ms）
- **人的感知有阈值**（振动太弱感觉不到）
- **人会适应**（一直振就不敏感了 —— 叫 habituation）

**所以触觉接口的评估指标不是"精度"，而是：**
- **辨识率** —— 用户能不能分清几种提示
- **反应时间** —— 从提示到动作多久
- **认知负荷** —— 会不会占用太多注意力
- **学习成本** —— 训练多久能上手

## 六、读这个项目的正确姿势

**这是本科毕设级别的硬件原型，不是产品。**

它演示了完整的**「感知 → 决策 → 触觉反馈」**闭环，但没做：
- 用户实验（辨识率、反应时间）
- 多方向编码（单电机只能提示"有障碍"，不能提示"在哪边"）
- 长时间佩戴的舒适性和功耗

**这正好是「想接着做」的方向** —— 见下。

## 七、自己动手

```cpp
// 四个版本就是迭代过程，按顺序读：
// 1. Sensor/Ultrasonic_Sensor_Ranging_Test/  → 先验证传感器
// 2. Sensor/                                  → 封装成模块
// 3. Final_singleloop/                        → 加反馈闭环
// 4. Final_Verison/                           → 最终版
```

**建议的改进方向：**
- **多方向编码** —— 用 3~4 个振子（左/右/前），空间编码不需要学习
- **强度映射实验** —— 距离 → 振动强度的曲线怎么设计最好用
- **用户实验** —— 这才是 Haptics 论文的核心：辨识率、反应时间、认知负荷
- **换成线性谐振致动器（LRA）** —— 比偏心转子电机响应更快、更省电
- **加 IMU** —— 检测佩戴者朝向，可以提示"相对行进方向"的障碍

> 📚 **深入方向**：Haptics、可穿戴计算、无障碍设计、人因工程
