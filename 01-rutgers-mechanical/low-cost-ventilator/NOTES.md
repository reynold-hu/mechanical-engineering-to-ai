# 原理讲解：低成本呼吸机（本科毕业设计）

> Rutgers ME Undergraduate Senior Design 2021
> **这是我本科阶段的收官项目** —— 纯机械 + 嵌入式，几乎没有算法。
> 它的价值不在技术含量，而在**「用有限资源解决真实问题」的工程判断**。

---

## 一、背景：为什么 2020 年需要这个

COVID-19 爆发初期，全球呼吸机短缺。传统 ICU 呼吸机：

| | 传统呼吸机 | 本项目 |
|:---|:---|:---|
| 价格 | 数万到十几万美元 | **目标几百美元** |
| 供应链 | 复杂、易断 | 用现成零件 |
| 用途 | ICU 重症 | **应急/过渡** |

**核心工程判断：不做"更好的呼吸机"，做"够用的、能快速造出来的呼吸机"。**

这叫 **frugal engineering（节俭工程）** —— 约束不是性能，是**可获得性**。

> ⚠️ **重要说明**：医疗设备有严格的监管（FDA/CE）。这个项目是**学术原型**，
> **从未用于临床**，也不应该被当作可用设备。它展示的是设计思路。

---

## 二、呼吸机的核心功能

**机械通气要控制三个量：**

| 参数 | 含义 | 典型值 |
|:---|:---|:---|
| **潮气量** (Tidal Volume) | 每次送气的气体量 | 6–8 mL/kg 体重 |
| **呼吸频率** (Respiratory Rate) | 每分钟呼吸次数 | 12–20 次/分 |
| **吸呼比** (I:E ratio) | 吸气时间 : 呼气时间 | 约 1:2 |

**加上安全约束：**
- **气道压力上限** —— 压力过高会撑破肺泡（气压伤），必须有限压保护
- **警报** —— 断电、堵塞、压力异常要报警

---

## 三、三种通气方式

| 类型 | 原理 | 复杂度 |
|:---|:---|:---|
| **有创** | 插管，直接向气管送气 | 高（需专业操作） |
| **无创** | 面罩 | 中 |
| **气囊挤压** | **机械臂挤压复苏气囊（Ambu bag）** | **低** ← 本项目思路 |

**挤压气囊路线的聪明之处：**

> 复苏气囊（Ambu bag）是**已经通过认证的医疗器械**，医院里到处都是。
> **我们不去设计"送气的部分"，只设计"挤压的部分"。**

**这绕开了最难的监管和制造环节** —— 不用做气路设计、不用做无菌处理。

## 四、技术实现

**从三个 `.ino` 文件能看出架构：**

```
ventilator.ino      主控逻辑（呼吸周期、参数设置）
motor.ino           电机控制（挤压动作）
pressure_sensor.ino 压力采集（安全保护）
```

**核心控制循环：**

```cpp
void loop() {
    // 吸气相
    motor_compress();                        // 挤压气囊
    delay(inspiratory_time);

    // 呼气相
    motor_release();                         // 松开
    delay(expiratory_time);

    // 安全检查（每个周期都要做）
    if (read_pressure() > PRESSURE_LIMIT) {
        emergency_stop();                    // 超压立即停止
        alarm();
    }
}
```

**用到的硬件（推测，从代码名看）：**
- **步进电机** —— 精确控制挤压量（比直流电机可控）
- **压力传感器** —— 气道压力监测
- **Arduino** —— 主控

## 五、安全设计：这个项目最重要的部分

**医疗设备的核心不是"能用"，是"失效时不会害死人"。**

| 风险 | 后果 | 对策 |
|:---|:---|:---|
| **压力过高** | 肺泡破裂（气压伤） | 压力传感器 + 硬性限压 |
| **断电** | 病人窒息 | 备用电源 / 手动模式 |
| **电机卡死** | 持续送气 | 看门狗 + 机械泄压阀 |
| **参数设置错误** | 通气不足/过度 | 输入范围校验 |

**关键原则：fail-safe（失效安全）。**
出问题时应该**停在"安全"的状态**（停止送气），而不是"继续运行"。

**机械泄压阀是最后的防线** —— 即使软件全挂了，物理阀门也会在超压时打开。
**纯软件的保护不算保护。**

---

## 六、这个项目教了什么

**技术之外的三件事：**

1. **约束驱动设计** —— 限制条件（成本、供应链、时间）反而让方案更清晰
2. **复用已认证部件** —— 用现成的气囊，而不是重造整个气路
3. **安全优先于功能** —— 医疗设备里，"不会伤害"比"效果好"更重要

**这些判断，在后来做机器人/软件时一样适用。**

## 七、自己动手

```
├── Ventillator Poster.jpg     ← 先看海报，了解整体设计
├── ventilator.ino             ← 主控逻辑
├── motor.ino                  ← 电机驱动
└── pressure_sensor.ino        ← 传感器
```

**建议的改进方向：**
- **加闭环** —— 现在是开环定时挤压，改成压力反馈闭环
- **参数界面** —— 加屏幕和旋钮，让医生能调参数
- **数据记录** —— 记录每个周期的压力/流量曲线，便于复盘
- **冗余设计** —— 双传感器、双电源、看门狗定时器
- **合规研究** —— 如果要真做，得研究 FDA 的 EUA（紧急使用授权）流程

> 呼吸生理学
