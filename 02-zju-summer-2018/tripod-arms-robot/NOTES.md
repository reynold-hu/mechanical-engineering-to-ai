## 一、串联 vs 并联：两种完全不同的结构

| | **串联**（如 UR5） | **并联**（如 Delta） |
|:---|:---|:---|
| 结构 | 关节一节套一节 | 多个臂**同时**连到同一个平台 |
| 刚度 | 低（误差逐级累积） | **高**（误差平均） |
| 工作空间 | 大 | **小** |
| 速度 | 慢（负载大） | **快**（电机都在底座上） |
| 正运动学 | 容易 | **难** |
| 逆运动学 | 难 | **容易** |

**关键洞察：两者正好相反。**

- **串联臂**：正解容易（连乘变换矩阵），逆解难（要解非线性方程组）
- **Delta**：**逆解容易**（每个臂独立算），正解难（三个圆求交）

**这就是为什么 Delta 适合做 3D 打印机和高速抓取** —— 需要快速精确定位，
而逆解（"去这个位置，电机转多少"）恰恰是控制系统最常问的问题。

## 二、Delta 机构长什么样

```
        ┌─────────────────────┐
        │   固定平台（底座）    │
        └──┬───────┬───────┬──┘
           │       │       │         ← 三个电机（120° 分布）
        ╱  │       │       │  ╲
     臂1 │   臂2    │    臂3   │      ← 主动臂（由电机驱动）
        ╲  │       │       │  ╱
         ╲ │       │       │ ╱
          ╲│       │       │╱
        ┌──┴───────┴───────┴──┐
        │   动平台（末端）      │      ← 装夹爪/打印头
        └─────────────────────┘
```

**参数：**
- `f` —— 固定平台边长（底座三角形）
- `e` —— 动平台边长（末端三角形）
- `rf` —— 主动臂长度
- `re` —— 从动臂（平行四边形连杆）长度

**每个臂是一组平行四边形连杆** —— 这保证动平台**只平移不旋转**（自由度 = 3）。

## 三、逆运动学推导（三步）

**问题：给定末端位置 (x, y, z)，求三个电机的角度 θ₁ θ₂ θ₃。**

**由于三个臂对称，只需要推导一个臂，另外两个旋转 120° 即可。**

### 第 1 步 · 坐标变换

把末端位置从**整体坐标**转到**以某个臂为基准的局部坐标**：

```python
# 以 1 号臂为基准（在 y 轴方向）
# 把末端位置绕 z 轴旋转，让该臂朝上
y1 = -y + f/(2*tan(60°))       # 投影到该臂所在平面
z1 = -z                        # 高度（注意 z 轴向下为正的约定）
```

### 第 2 步 · 加入动平台尺寸

```python
a = (x1² + y1² + z1² + rf² - re² - e²/4 - f²/4) / (2*z1)
b = (f/2 - y1) / z1            # 或类似形式（取决于坐标约定）
c = rf
```

### 第 3 步 · 解二次方程（余弦定理）

**这是最关键的一步。** 主动臂、从动臂、以及"目标点到电机轴的距离"构成一个三角形：

```
             电机轴
              ╱│
        rf  ╱  │
          ╱    │  目标到电机轴的距离
        ╱      │
      ╱ θ      │
     端 ────────┘
          re
```

用**余弦定理**：

```python
# a*x² + b*x + c = 0  形式的二次方程
# 判别式
disc = b² - 4*a*c

if disc < 0:
    # 目标点超出工作空间 —— 无解
    return None

# 两个解对应「肘部朝上」和「肘部朝下」
theta = 2 * atan( (-b + sqrt(disc)) / (2*a) )    # 或 -sqrt，看取哪支
```

**要点：**
- **判别式 < 0 → 无解**，说明目标点够不着（超出工作空间）
- **两个解 → 肘上/肘下**，实际控制时要选一个（通常选离当前位形近的，避免跳变）

## 五、G-code 解析器（我当年写的部分）

`Gcode_interpreter CN.ino` 是一个**手写的极简 G-code 解析器**：

```cpp
// 指令格式：G01 X60 F5000
// G = 指令类型，X = 目标位置，F = 进给速度
int parameter[3] = {0,0,0};   // 分别存 G / X / F

void loop() {
    UART_RX = Serial.read();
    do {
        switch(UART_RX) {
            case 'G': state = 0; break;    // 切到 G 参数槽
            case 'X': state = 1; break;    // 切到 X 参数槽
            case 'F': state = 2; break;    // 切到 F 参数槽
        }
        readtype = 1;                      // 后续读到的是数字
    } while (...)                          // 直到回车结束
}
```

**逻辑：一个状态机 —— 遇到字母切换参数槽，遇到数字累加。**

**没有用 GRBL 之类的现成库**，原因有二：一是当时想自己搞清楚协议，

这个机器人是**从 Delta 3D 打印机改造**的，所以最自然的想法是
「直接把打印机固件的运控搬过来」。**但这条路走不通：**

| 固件 | 许可证 |

| Marlin | 🔴 GPL-3.0 |
| Klipper | 🔴 GPL-3.0 |
| GRBL | 🔴 GPL-3.0 |
| Candle | 🔴 GPL-3.0 |
| Teacup | 🔴 GPL-2.0 |

**整个生态都是 GPL**（从 Sprinter / GRBL 一脉相承）。

**关键认识：Delta 逆运动学的数学和代码来源无关。**
不管代码来自打印机固件、通用运动学库，还是论文推导 ——
**它算的都是同一件事**。所以选许可证兼容的实现就行。
